# Aurora PostgreSQL infrastructure

`modules/aurora-postgresql` provisions the Aurora PostgreSQL cluster that backs the tenant registry
(`fineract_tenants`) and the per-tenant databases. `environments/dev` is the dev instantiation of it.

```bash
cd environments/dev
terraform init
terraform apply -var 'allowed_cidr_blocks=["<your CIDR>"]'
```

The master credentials are generated by Terraform and stored in Secrets Manager; the secret ARN is a
Terraform output. State is not stored in this repository.

## Running the build against the managed instance

The Gradle tasks and the test suites read the connection settings from the environment (Gradle
properties of the same name take precedence), so no build file has to be edited:

| Variable | Gradle property | Meaning |
| --- | --- | --- |
| `FINERACT_DB_HOST` | `dbHost` | database host, defaults to `localhost` |
| `FINERACT_DB_PORT` | `dbPort` | database port |
| `FINERACT_DB_USER` | `dbUser` | user of the tenant registry |
| `FINERACT_DB_PASSWORD` | `dbPassword` | password of that user |
| `FINERACT_DB_NAME` | `dbName` | tenant registry database |
| `FINERACT_DB_CONNECTION_PARAMS` | `dbConnectionParams` | JDBC parameters, e.g. `sslmode=require` |
| `FINERACT_DB_MAINTENANCE_NAME` | `dbMaintenanceName` | database `createPGDB`/`dropPGDB` connect to; Aurora has no server-level connection |

```bash
export FINERACT_DB_HOST=<cluster writer endpoint>
export FINERACT_DB_USER=fineract FINERACT_DB_PASSWORD=<secret> FINERACT_DB_MAINTENANCE_NAME=fineract_tenants
./gradlew :fineract-provider:createPGDB -PdbName=fineract_default
./gradlew :integration-tests:test
```

Liquibase can also be driven directly with the contexts and changelog parameters the application uses:

```bash
./gradlew :fineract-provider:liquibaseTenantCommand -PdbName=fineract_default -PliquibaseCommand='status'
./gradlew :fineract-provider:liquibaseTenantCommand -PdbName=fineract_default -PliquibaseCommand='tag before_release'
./gradlew :fineract-provider:liquibaseTenantCommand -PdbName=fineract_default -PliquibaseCommand='rollback before_release'
```

An empty database needs the Flyway switch baseline first (`-PliquibaseInitialSwitch=true`), exactly like
`TenantDatabaseUpgradeService` does. Note that changesets which only insert reference data have no
inverse, so a rollback has to target a tag that precedes them.

## Connection pool sizing

Each tenant gets its own HikariCP pool, so the cluster's `max_connections` (`max_connections`
variable, 400 in dev) has to cover `tenants * fineract.tenant.config.max-pool-size` plus headroom.
`ConcurrentTenantPoolSmokeTest` in `integration-tests` asserts that this holds; it runs only when
`FINERACT_DB_HOST` is set and can be sized with `FINERACT_SMOKE_TENANT_DATABASES`,
`FINERACT_SMOKE_MAX_POOL_SIZE`, `FINERACT_SMOKE_SERVER_MAX_CONNECTIONS` and
`FINERACT_SMOKE_REQUESTS_PER_TENANT`.
