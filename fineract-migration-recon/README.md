# Migration reconciliation harness

Proves that a migrated Fineract database still holds the same ledger as the source. A row-count match does not prove
that, so the harness reconciles at three levels and fails on any variance:

| Level | What it compares | Why row counts miss it |
| --- | --- | --- |
| Row counts | exact `count(*)` per base table per tenant | — |
| Financials | loan balances, journal entries and savings balances aggregated by currency (and by office/account/type for journals) | a truncated `DECIMAL(19,6)` or a silently coerced `NULL` keeps the row |
| Trial balance | debits equal credits per currency, on both sides | a dropped journal leg changes the count on both sides equally if a compensating row is also lost |
| Sequences | the target's next generated id is above every migrated id | neither a logical dump nor a DMS full load carries identity state; the first insert after cutover collides |

Comparisons are exact. Amounts are compared with `BigDecimal.compareTo`, so `10.0` and `10.000000` reconcile but
`1500.000000` and `1499.999999` do not.

## Running it

```
scripts/migrate/reconcile.sh scripts/migrate/migration.env
```

or directly:

```
./gradlew :fineract-migration-recon:reconcile -Precon.config=/path/to/recon.properties
```

Exit code 0 means zero variance across every tenant; 1 means a variance was found. A report with no tenants is not a
pass. Both `reconciliation-report.txt` (the sheet the DBA signs) and `reconciliation-report.json` are written to
`output.directory`.

### recon.properties

```properties
source.engine=mariadb          # mariadb | postgresql
source.host=source-db.internal
source.port=3306
source.username=recon
source.password=...            # generated by scripts/migrate/reconcile.sh into a 0600 temp file
source.registryDatabase=fineract_tenants
target.engine=postgresql
target.host=target-db.internal
target.port=5432
target.username=recon
target.password=...
target.registryDatabase=fineract_tenants
tenants=                       # empty means every tenant in the registry
output.directory=build/recon
```

Credentials come from configuration, never from `tenant_server_connections.schema_password`: that column is AES
encrypted with the tenant master password (see Q-DB-6) and the harness has no business decrypting it. A read-only
database role is enough.

## Tests

`CrossEngineReconciliationTest` runs MariaDB and PostgreSQL containers, seeds the same ledger into both, and asserts
that a faithful copy reconciles while a one-millionth-unit repayment difference and an unadvanced sequence do not. It
skips when Docker is unavailable. The remaining tests drive the comparator with seeded discrepancies.
